The S1 & S2 GPU Belief-Propagation Decoders

An implementation guide to the CUDA kernels.

1 · Overview

For each shot, the decoder receives a syndrome. It returns a correction consistent with that syndrome and a prediction for the logical observables.

The package uses a sequence of increasingly expensive decoders. Each stage receives only the shots deferred by the preceding stage:

The decoding sequence. S1 and S2 are the GPU stages.

S1 and S2 are both belief-propagation (BP) decoders that run on the GPU. Both stages employ a layered update schedule, but use different update and acceptance rules.

S1 — fixed-iteration BP

S1 executes a fixed number of layered BP iterations without early termination. Following the final iteration, residual_count determines which shots satisfy \(H\hat{\boldsymbol{\epsilon}}=s\).

S2 — the relay stage

S2 implements relay-BP, in which an outer loop performs multiple BP solves, referred to as legs, with a per-iteration memory term and randomized memory strengths. The stage records converged candidate corrections.

S2 is applied only to shots not accepted by S1.

2 · Glossary

The decoding problem

  • Parity-check matrix \(H\) — a binary matrix of size \(m\times n\). Each of the \(m\) rows is a check (a parity constraint); each of the \(n\) columns is a variable (a possible error mechanism). \(H_{cv}=1\) means variable \(v\) participates in check \(c\).
  • Tanner graph — the same information drawn as a graph: variable nodes and check nodes, with an edge wherever \(H_{cv}=1\). BP is "message passing" along these edges. An edge is indexed by a flat number \(e\in\{0,\dots,E-1\}\), where \(E\) is the total number of 1s in \(H\).
  • Syndrome \(s\) — the observed outcome, one bit per check (\(m\) bits). We want a correction \(\hat{\boldsymbol{\epsilon}}\) (one bit per variable) with \(H\hat{\boldsymbol{\epsilon}}=s \pmod 2\).
  • Prior LLR \(\lambda_v\) — the prior odds for variable \(v\), expressed as a log-likelihood ratio: \(\lambda_v=\log\frac{1-p_v}{p_v}\). A large positive value favors no error; a negative value favors an error. In code this is channel_llr.
  • Posterior LLR \(L_v\) — BP's current best belief about variable \(v\), same sign convention. The hard decision is \(\hat{\epsilon}_v = \mathbb{1}[L_v<0]\). In code: posterior.
  • c2v message — a check-to-variable message \(L_{c\to v}\). There is one float per Tanner edge in the c2v array.
  • Convergence — a shot has converged when its hard decision satisfies every check (\(H\hat{\boldsymbol{\epsilon}}=s\)). The code verifies this directly with the residual_count kernel.
  • Shot / batch lane — one decoding instance. We decode \(B\) of them at once; "lane \(b\)" is the \(b\)-th shot. Every kernel does the same work \(B\) times in parallel.
Tanner-graph representation of a parity-check matrix. BP passes messages along its edges.

GPU terms used here

Section 3 describes the execution model these kernels assume — SMs, thread blocks, warps, and the memory hierarchy. Four bindings are specific to this decoder:
  • Thread — one kernel execution, normally tied to a batch lane \(b\) and, in the check kernels, to a subset of the edges incident on one check.
  • Warp width — the kernels set _BWARP = 32 so that one warp spans 32 batch lanes, which is what makes their global-memory reads coalesce.
  • Block shape — the check kernel launches \(32\times32=1024\) threads per block: 32 batch lanes along x and 32 edge-slice warps along y.
  • CUDA graph — a recorded sequence of kernel launches that replays with one call. S1 and S2 use graphs to strip Python and driver overhead from their many short launches.
The guide defines the remaining CUDA identifiers where each excerpt first uses them.

3 · How a GPU runs a kernel

A kernel is a function that the GPU executes across many threads in parallel. Every thread runs the kernel, and its coordinates let the code distinguish that thread from the others when needed.

CUDA organizes those threads in four levels: a kernel launch creates a grid, the grid contains blocks, and each block contains threads that execute in groups called warps. The decoder maps checks and batch lanes onto this hierarchy. The picture below gives the map; the rest of this section explains the parts used later.

The solid arrows lead from the launch to block assignment. The dashed arrow zooms into the assigned block to show how its threads are grouped.

3a · Streaming multiprocessors and thread blocks

A GPU contains many streaming multiprocessors (SMs). When a kernel launches, the GPU assigns each block to one SM. A block stays on that SM until it finishes, although one SM may host several blocks at the same time.

Blocks must be able to run in any order. They cannot use a grid-wide barrier to wait for one another. This fits the check kernel in Section 6a: each block owns one check and writes a separate set of message edges, so the blocks can proceed independently.

3b · Warps

An SM executes a block's threads in groups of 32 called warps. The 32 threads in a warp issue the same instruction together. If there is control flow in the program that causes different threads to take different branches, the SM must run each branch in turn and mask off the threads that do not take it. This is known as warp divergence and can cause a huge hit on performance. The best performance is usually achieved when kernels are written so that all threads in a warp execute the exact same instruction so that there is no warp divergence.

Threads 0–31 form the first warp, threads 32–63 the second, and so on. In a two-dimensional block, threadIdx.x varies fastest. A block that is 32 threads wide in x therefore places each row in one warp. Section 6a uses this rule to explain the decoder's \((32, 32)\) check blocks.

When one warp waits for a memory read, the SM can run another ready warp. The keeps the GPU busy and helps hide latency from expensive memory reads.

3c · The memory hierarchy

There are three types of memory on the GPU.

MemoryVisible toLifetimeUsed in our decoding kernels to store
Registersone threadthe threadtemporary values used by one thread while computing messages
Shared memoryone blockthe blockcheck data reused by the threads in one block, along with intermediate results they combine
Global memoryevery blockthe allocationdecoder inputs and state shared across blocks or preserved between kernel launches

Registers hold a thread's ordinary local values. Shared memory is a fast scratchpad for one block. Global memory is visible to the entire grid and keeps the decoder state between kernel launches. Global memory access is the most expensive and we want to write out kernels in a way that minimizes its use.

3d · Memory coalescing

When the 32 threads in a warp read from global memory, the GPU can combine their requests into a small number of memory transactions. This works best when the requested values are stored next to one another at consecutive memory addresses. This is called memory coalescing. Values scattered across memory require more transactions and take longer to read.

The decoder processes a batch of \(B\) shots at once. Within that batch, the shots are numbered \(b=0,\ldots,B-1\); “batch lane \(b\)” simply means the shot at position \(b\). The decoder stores this batch dimension last. The thread assigned to shot \(b\) reads element \(b\), so the 32 threads in a warp read one contiguous row. Section 5 explains this in more detail.

4 · Belief propagation formulation

In this section, we outline how the belief propagation algorithm works. We discuss the exact sum-product updates and their min-sum approximation.

4a · Posterior distribution

Let \(\boldsymbol{\epsilon}\in\{0,1\}^n\) say which error mechanisms occurred. Before observing the syndrome, the model assigns each bit a prior probability \(P_v(\epsilon_v)\). After observing the syndrome \(s\), only physical errors consistent with the syndrome are possible:

$$ P(\boldsymbol{\epsilon}\mid s) \propto \prod_v P_v(\epsilon_v) \prod_c \mathbf{1}\!\left[ \bigoplus_{v\in\mathcal N(c)} \epsilon_v=s_c \right]. $$

Computing this distribution directly would require considering an exponential number of different physical error pattens. Belief propagation instead passes messages around the Tanner graph to compute each variable's marginal odds.

4b · High-level intuition for what BP does

BP works by repeatedly turning local parity constraints into updated beliefs about individual variables. A variable tells a check what it currently believes from its prior and its other checks. The check then asks what value that variable would need in order to satisfy the measured parity, given what all the other variables reported. Each message excludes the recipient's previous contribution so that information is not immediately fed back to its source.

Example. Suppose \(\epsilon_a\oplus\epsilon_b\oplus\epsilon_c=1\). If \(b\) and \(c\) both strongly favor 0, the check sends \(a\) a strong message favoring 1. If they favor 1 and 0, the message to \(a\) favors 0. If either belief has a small magnitude LLR (meaning it is uncertain), the message to \(a\) will also have a small magnitude.

Each variable combines these independent-looking messages by adding their LLRs. On a tree, cutting the edge along which a message is sent divides the graph into two disconnected components. The message therefore summarizes only the evidence on the sender’s side, with no double counting, so BP computes exact marginals. In a graph with cycles, old evidence can eventually travel around a loop and return; BP becomes an approximation.

4c · The exact sum-product updates

The decoder stores beliefs as LLRs. A positive LLR favors \(\epsilon_v=0\), a negative LLR favors \(\epsilon_v=1\), and a larger magnitude means greater confidence. We denote the prior by \(\lambda_v\), the check-to-variable message by \(L_{c\to v}\), and the stored posterior by \(L_v\).

The BP algorithm

Initialization (once per solve). Before the main BP loop, set every check message to zero and every posterior to its prior: \(L_{c\to v}=0\) and \(L_v=\lambda_v\).

Main BP loop. Each iteration processes all \(K\) check layers in order. Within each layer, the quantities are evaluated in the following order:

$$ \text{posterior }L_v \;\longrightarrow\; \text{variable-to-check }L_{v\to c} \;\longrightarrow\; \text{check-to-variable }L^{\mathrm{new}}_{c\to v} \;\longrightarrow\; \text{new posterior }L^{\mathrm{new}}_v. $$
  1. Choose the next check layer. The implementation partitions the checks into \(K\) layers and processes them in order. Within a layer, everything runs in parallel.
  2. Compute the variable-to-check messages. For every edge \((c,v)\) in the layer, variable \(v\) sends check \(c\) its prior plus the messages from its other neighboring checks: $$ L_{v\to c}=L_v-L_{c\to v} =\lambda_v+\sum_{c'\in\mathcal N(v)\setminus\{c\}}L_{c'\to v}. $$ The kernel obtains this value by subtracting \(c\)'s old contribution from the stored posterior.
  3. Compute the check-to-variable messages. Check \(c\) now combines the messages from every variable except the destination \(v\): $$ L^{\mathrm{new}}_{c\to v}=2\,\operatorname{atanh}\!\left( (-1)^{s_c} \prod_{v'\in\mathcal N(c)\setminus\{v\}} \tanh\!\frac{L_{v'\to c}}{2} \right). $$ This is the exact sum-product check rule. The syndrome \(s_c\) determines the required parity and therefore the outgoing sign.
  4. Update the posterior beliefs. Store the new check-to-variable messages, then recompute every posterior touched by the layer: $$ L^{\mathrm{new}}_v=\lambda_v+\sum_{c\in\mathcal N(v)}L_{c\to v}. $$ The next layer therefore sees the newest available beliefs.

Repeat these four steps until all \(K\) layers have been processed, completing one iteration. Then begin the next iteration. Stop after the configured number of iterations.

Decision and verification (after the loop). Output \(\hat\epsilon_v=\mathbf 1[L_v<0]\), then explicitly test \(H\hat{\boldsymbol\epsilon}=s\). Only a candidate that passes this test is marked converged.

Message rule and update schedule. Step 3 calculates each check-to-variable message. Sum-product uses the exact formula shown above, while in the next section we will consider the cheaper min-sum approximation. Step 4 immediately incorporates each layer’s new messages into the posterior beliefs, so the next layer uses the latest available information. This immediate update is what makes the schedule layered.

4d · From sum-product to min-sum

Start with the exact check update from step 3 above. Because tanh is an odd function, each incoming factor can be split into its sign and magnitude:

$$ \tanh\!\frac{L_{v'\to c}}{2} =\operatorname{sign}(L_{v'\to c}) \tanh\!\frac{|L_{v'\to c}|}{2}. $$

Substituting this into the product separates the signed factors from the nonnegative factors:

$$ (-1)^{s_c}\!\prod_{v'\ne v}\tanh\!\frac{L_{v'\to c}}{2} =\underbrace{\left[(-1)^{s_c}\!\prod_{v'\ne v} \operatorname{sign}(L_{v'\to c})\right]}_{\text{sign}} \underbrace{\left[\prod_{v'\ne v}\tanh\!\frac{|L_{v'\to c}|}{2}\right]}_{\text{magnitude}}. $$

The second bracket is nonnegative, and atanh preserves the sign of its input. Therefore the sign of the outgoing check message is exactly

$$ \sigma_{c\to v}=(-1)^{s_c} \prod_{v'\in\mathcal N(c)\setminus\{v\}} \operatorname{sign}(L_{v'\to c}), $$

while its magnitude is

$$ 2\,\operatorname{atanh}\!\left( \prod_{v'\ne v}\tanh\!\frac{|L_{v'\to c}|}{2} \right). $$

Why does a minimum approximate this expression? Every factor \(\tanh(|L_{v'\to c}|/2)\) lies between 0 and 1, so their product cannot exceed its smallest factor. Because tanh and atanh are increasing, the exact outgoing magnitude therefore satisfies

$$ \left|L_{c\to v}\right|\le \min_{v'\in\mathcal N(c)\setminus\{v\}}|L_{v'\to c}|. $$

When the other inputs are reliable, their tanh factors are close to 1 and the weakest input dominates the product. Min-sum turns that observation into an approximation: it replaces the entire tanh/atanh calculation with the smallest incoming magnitude:

$$ \mu_{c\to v}=\min_{v'\in\mathcal N(c)\setminus\{v\}}|L_{v'\to c}|, \qquad L^{\mathrm{MS}}_{c\to v}=\alpha\,\sigma_{c\to v} \max(\mu_{c\to v}-\beta,0). $$

Pure min-sum uses \(\alpha=1\) and \(\beta=0\). It preserves the exact sign but usually overestimates the magnitude, so normalized min-sum uses \(\alpha<1\), offset min-sum uses \(\beta>0\), or both. In the code, \(\beta\) is the offset argument. S1 ramps \(\alpha\) over iterations as \(\alpha(t)=\alpha_{\max}(1-e^{-(t+1)/\tau})\); Section 6f lists the configured values.

4e · The min1 / min2 trick

Computing \(\mu_{c\to v}\) separately for every neighbor would be quadratic in the check's degree. Instead, we find the two smallest magnitudes over all neighbors once:

$$m_1 = \min_{v'} |L_{v'\to c}|,\qquad m_2 = \text{second-smallest}_{v'} |L_{v'\to c}|.$$

The excluded minimum for any neighbor is then:

$$\mu_{c\to v} = \begin{cases} m_2 & \text{if } v \text{ is the argmin (the one holding } m_1) \\ m_1 & \text{otherwise}\end{cases}$$

The check kernel makes two passes over the edges. The first finds \(m_1\), \(m_2\), and the sign parity. The second uses those values to write each outgoing message.

4f · Flooding vs. layered schedule

BP can update messages in two orders:

  • Flooding — update all checks, then all variables, and repeat.
  • Layered (what we use) — split the \(m\) checks into \(K\) contiguous groups ("layers"). After updating the check-to-variable messages in one layer, recompute the posterior of every variable that layer touched: $$ L_v \leftarrow \lambda_v+\sum_{c\in\mathcal N(v)}L_{c\to v}. $$ Layer \(k+1\) therefore uses the posterior updates made by layer \(k\) within the same iteration.
Each blue step forms \(L_{v\to c}=L_v-L_{c\to v}^{\mathrm{old}}\) on the fly, then stores \(L_{c\to v}^{\mathrm{new}}\). The green step recomputes the touched \(L_v\) posteriors. The corresponding GPU kernels are layered_check_compute_inplace and layered_var_resync_subset.

5 · How the data is laid out in memory

Every per-variable, per-edge, and per-check array stores the batch dimension last, so it is the fastest-changing axis:

# shapes, batch size B
posterior : (n,   B)  float32   # variable beliefs L_v
prior     : (n,   B)  float32   # channel LLR λ (or S2's per-iter bias)
c2v       : (E+1, B)  float32   # check→variable messages; last row is a zero sentinel
synd      : (m,   B)  uint8     # syndrome bits

This order matches the way the kernel assigns work. Thread \(b\) of a warp handles lane \(b\), so the 32 reads of posterior[v, b] for \(b=0..31\) land on 32 consecutive floats. The GPU can serve that coalesced access with fewer memory transactions than it could if the batch dimension came first.

Connectivity tables

The Tanner-graph adjacency relations are precomputed on the CPU and transferred to the GPU. Since node degrees vary, the tables are padded to fixed widths, which permits branch-free indexing:

  • c2e[c, k] and c_neigh[c, k] store the edge and variable indices of the \(k\)-th neighbor of check \(c\); c_degrees[c] stores the unpadded degree.
  • v2e[v, k] stores the incident edge indices of variable \(v\) and is padded to DV_PAD.
  • c2v[e, b] stores the check-to-variable message \(L_{c\to v}\) on edge \(e\) for batch lane \(b\). The indices in c2e and v2e address the same rows of c2v: check kernels use c2e to write messages, whereas variable kernels use v2e to read and sum them.
  • c2v contains an additional zero row at index \(E\). Padding entries reference this sentinel row and therefore contribute zero to message sums.

5a · Blocks, threads, and coordinates

A CUDA launch has two shapes. The grid says how many blocks to create. The block says how many threads to put in each block. CuPy passes both shapes at the launch site:

# Python / CuPy
kernel(
    grid=(grid_x, grid_y),       # how many blocks to launch
    block=(threads_x, threads_y),# threads inside each block
    args=(...),
)

Once the kernel starts, each thread can read four built-in values. These names belong to CUDA; the kernel does not declare them or receive them as arguments.

Built-inMeaningFields
threadIdxThis thread's coordinate inside its block..x, .y, .z
blockIdxThis block's coordinate inside the grid..x, .y, .z
blockDimThe block shape supplied by CuPy..x, .y, .z
gridDimThe grid shape supplied by CuPy..x, .y, .z

The CUDA headers expose them roughly like this:

const uint3 threadIdx;

const dim3 blockDim;

These kernels use only the x and y coordinates; CUDA sets each omitted z dimension to 1.

What .x and .y do here

CoordinateUsual job in these kernels
blockIdx.xSelect a check row or a variable.
blockIdx.ySelect a group of batch lanes.
threadIdx.xSelect one shot within that batch group; normally one 32-thread warp spans 32 shots.
threadIdx.ySelect which warp processes a slice of a check's edges.
blockDim.xTell the kernel how many batch lanes one x-row of the block contains.

Many kernels combine the grid's y coordinate with the thread's x coordinate to get a batch index:

int b = blockIdx.y * blockDim.x + threadIdx.x;

With blockDim.x = 32, blockIdx.y = 3, and threadIdx.x = 7, the result is b = 3 × 32 + 7 = 103. The final block is not always full, so the kernel checks b < B before touching memory.

6 · S1 decoder implementation

S1, implemented by S1LayeredBP, performs a fixed number of layered BP iterations and evaluates the convergence condition for each shot. We first describe the check and posterior-update kernels, followed by the utility kernels and the Python orchestration.

The module defines the following default padding widths and thread geometry. The stage wrappers replace the padding widths by the values stored in the selected NPZ artifact.

_DC_PAD = 160
_DV_PAD = 24
_BWARP = 32
_N_WARPS = 32

6a · Min-sum check kernel — layered_check_compute_inplace

telescoping_decoder/kernels/s1_layered_bp.py · layered_check_compute_inplace

This kernel implements the min-sum update of Sections 4d–4e. For a layer of \(L\) checks the grid is \(L\times\lceil B/32\rceil\) blocks of \(32\times32=1024\) threads. A block therefore owns one check and at most 32 shots: blockIdx.x picks the check's position in the layer and blockIdx.y picks the group of shots, while inside the block threadIdx.x picks one shot from that group and threadIdx.y picks one of the 32 warps that partition the check's incident edges. When \(B>32\), the same check is handled by \(\lceil B/32\rceil\) blocks.

extern "C" __global__ __launch_bounds__(BW * N_WARPS, 2)
void layered_check_compute_inplace(
    const int*   __restrict__ c2e,
    const int*   __restrict__ c_neigh,
    const int*   __restrict__ check_order,
    const int*   __restrict__ c_degrees,
    const unsigned char* __restrict__ synd,
    const float alpha,
    const float offset,
    const int B, const int m, const int n, const int E,
    const int layer_start,
    const float* __restrict__ posterior,
    float* __restrict__ c2v
) {{

The four size parameters describe the parity-check matrix and the current batch:

ParameterMeaning
BNumber of shots (batch columns) processed by this launch.
mNumber of parity checks, equal to the number of rows of \(H\).
nNumber of variables, equal to the number of columns of \(H\).
ENumber of Tanner-graph edges, equal to the number of nonzero entries in \(H\).

Consequently, posterior[v * B + b] selects variable v for shot b, while c2v[e * B + b] selects edge e for that shot. This particular kernel directly uses only B and m; n and E remain in the shared launch signature but are not referenced in its body.

BW is distinct from B. It is the compile-time width of the block's x dimension and is fixed at 32, so the 32 batch lanes along x form one hardware warp. N_WARPS is also fixed at 32 and gives the number of edge-slice warps in the block. Thus, BW * N_WARPS = 1024 threads are assigned to each check block.

Step 1 — thread assignment

    int c_pos = layer_start + blockIdx.x;  // Position in the flattened check schedule.
    if (c_pos >= m) return;
    int c = check_order[c_pos];  // Actual parity-check row processed by this block.
    int dc_c = c_degrees[c];  // Number of Tanner edges incident on check c.

    int tx  = threadIdx.x;  // Batch lane within a warp: 0, ..., BW-1.
    int wid = threadIdx.y;  // Warp assigned to one slice of this check's edges.
    int b   = blockIdx.y * BW + tx;  // Shot index in the current batch.

    int k_start = (dc_c * wid) / N_WARPS;  // First edge position assigned to this warp.
    int k_end   = (dc_c * (wid + 1)) / N_WARPS;  // One past the last assigned edge position.

check_order maps each position in the schedule to a row of the parity-check matrix. For example, the mapping [4, 1, 3, 0, 2] assigns check 4 to schedule position 0, check 1 to position 1, and so forth. This mapping permits checks to be assigned to different layers without rearranging the rows of the matrix. S1 currently uses the identity mapping [0, 1, 2, ..., m-1]; consequently, the checks retain their original matrix order. Checks assigned to the same layer are evaluated concurrently.

The k_start/k_end calculation is separate from layer construction. It divides the selected check's dc_c incident edges among the 32 warps; it does not reorder checks or define layers.

Step 2 — shared-memory initialization

    // Partition one shared-memory buffer into non-overlapping typed arrays.
    extern __shared__ unsigned char smem_raw[];  // Raw shared-memory buffer.
    int*   sh_c2e         = (int*)smem_raw;  // Edge IDs for check c.
    int*   sh_nbr         = sh_c2e + DC_PAD;  // Neighboring variable IDs for the corresponding edge.
    float* part_min1      = (float*)(sh_nbr + DC_PAD);  // Smallest magnitude found by each thread.
    float* part_min2      = part_min1 + N_WARPS * BW;  // Second-smallest magnitude found by each thread.
    int*   part_argmin1   = (int*)(part_min2 + N_WARPS * BW);  // Edge position that produced each thread's part_min1.
    int*   part_count_neg = part_argmin1 + N_WARPS * BW;  // Number of negative messages found by each thread.

    int total_threads = BW * N_WARPS;  // Threads in this block.
    int linear_tid = wid * BW + tx;  // This thread's index within the block.
    for (int i = linear_tid; i < dc_c; i += total_threads) {{  // Copy the edge positions assigned to this thread.
        sh_c2e[i] = c2e[c * DC_PAD + i];
        sh_nbr[i] = c_neigh[c * DC_PAD + i];
    }}
    __syncthreads();

The threads cooperatively copy the neighbor table from global memory to shared memory, after which both edge passes reuse the cached representation. The __syncthreads() barrier ensures that the copy is complete before any thread consumes it. The extern __shared__ qualifier indicates that the shared-memory size is supplied at launch time.

Step 3 — local minima and sign parity

    int s_idx = synd[c * B + b];

    float min1 = 1e30f, min2 = 1e30f;
    int argmin1 = -1;
    unsigned my_signs = 0u;
    int slice_idx = 0;
    for (int k = k_start; k < k_end; k++) {{
        int e = sh_c2e[k];
        int v_idx = sh_nbr[k];
        float v = posterior[v_idx * B + b] - c2v[e * B + b];
        my_signs |= ((unsigned)(v < 0.0f) << slice_idx);
        float av = fabsf(v);
        if (av < min1) {{ min2 = min1; min1 = av; argmin1 = k; }}
        else if (av < min2) {{ min2 = av; }}
        slice_idx++;
    }}
    int count_neg = __popc(my_signs);

The quantity v is the variable-to-check message \(L_{v\to c}=L_v-L_{c\to v}\), and min1 and min2 implement the construction in Section 4e. S1 packs edge signs into the 32-bit unsigned integer my_signs and uses __popc to count negative inputs. S2 uses a 64-bit mask and __popcll for its higher-degree checks.

Step 4 — reduction over warps

Each warp produces partial values over its assigned edge interval. These values are written to shared memory, after which warp 0 reduces the results over all 32 warps to obtain the check-wide minima and negative count:

    part_min1     [wid * BW + tx] = min1;
    part_min2     [wid * BW + tx] = min2;
    part_argmin1  [wid * BW + tx] = argmin1;
    part_count_neg[wid * BW + tx] = count_neg;
    __syncthreads();

    if (wid == 0) {{
        #pragma unroll
        for (int w = 1; w < N_WARPS; w++) {{
            float w_min1      = part_min1     [w * BW + tx];
            float w_min2      = part_min2     [w * BW + tx];
            int   w_argmin1   = part_argmin1  [w * BW + tx];
            int   w_count_neg = part_count_neg[w * BW + tx];
            count_neg += w_count_neg;
            if (w_min1 < min1) {{
                float new_min2 = (min1 < w_min2) ? min1 : w_min2;
                min1 = w_min1; argmin1 = w_argmin1; min2 = new_min2;
            }} else if (w_min1 == min1) {{
                int new_argmin1 = (w_argmin1 < argmin1) ? w_argmin1 : argmin1;
                float new_min2 = (min2 < w_min2) ? min2 : w_min2;
                if (w_min1 < new_min2) new_min2 = w_min1;
                argmin1 = new_argmin1; min2 = new_min2;
            }} else {{
                float new_min2 = (min2 < w_min1) ? min2 : w_min1;
                min2 = new_min2;
            }}
        }}
        part_min1     [tx] = min1;
        part_min2     [tx] = min2;
        part_argmin1  [tx] = argmin1;
        part_count_neg[tx] = count_neg;
    }}
    __syncthreads();

    min1      = part_min1     [tx];
    min2      = part_min2     [tx];
    argmin1   = part_argmin1  [tx];
    count_neg = part_count_neg[tx];

The reduction retains the two smallest magnitudes and the index of the smallest magnitude while accumulating the negative count. Following the second __syncthreads() barrier, each thread has access to the same check-wide values \(m_1\), \(m_2\), \(\operatorname{argmin}\), and sign count.

Step 5 — outgoing message evaluation

This loop computes and stores the outgoing check-to-variable message for each edge. The message sign is the parity of the other incoming signs, adjusted by the syndrome bit. Its magnitude is the smallest incoming magnitude excluding that edge—\(m_2\) if the edge supplied \(m_1\), and \(m_1\) otherwise—then reduced by the offset, clipped at zero, and scaled by alpha.

    int parity = (count_neg + s_idx) & 1;
    float pre = (parity ? -alpha : alpha);

    int slice_idx2 = 0;
    for (int k = k_start; k < k_end; k++) {{
        int e = sh_c2e[k];
        float min_excl = (k == argmin1) ? min2 : min1;
        // Offset min-sum: subtract a positive offset to approximate
        // sum-product. With offset=0 this is pure min-sum. Typical
        // offset values are 0.5 - 1.5 depending on check degree.
        min_excl = fmaxf(min_excl - offset, 0.0f);
        float sign_k = ((my_signs >> slice_idx2) & 1u) ? -1.0f : 1.0f;
        float new_msg = pre * sign_k * min_excl;
        c2v[e * B + b] = new_msg;
        slice_idx2++;
    }}
In-place update. Distinct checks have disjoint edge sets; therefore, two blocks cannot write the same c2v[e] entry and atomic operations are unnecessary.

6b · Sum-product check kernel — sum_product_check_compute_inplace

telescoping_decoder/kernels/s1_layered_bp.py · sum_product_check_compute_inplace

Section 4c defines the exact sum-product update. For dense checks, this update can provide improved convergence relative to min-sum. The corresponding kernel retains the launch geometry, shared-memory layout, and two-pass structure of the min-sum kernel, but evaluates the magnitude in the log-tanh domain.

The exact check magnitude is \(L_{c\to v}=2\,\operatorname{atanh}\!\big(\prod_{v'\neq v}\tanh\frac{|L_{v'\to c}|}{2}\big)\). To transform the product into a sum, we define

$$g(x) = -\log \tanh\!\tfrac{x}{2},\qquad\text{which satisfies } g(g(x))=x.$$

The message magnitude can then be written as \(g\big(\sum_{v'\neq v} g(|L_{v'\to c}|)\big)\). The total sum is computed once, and the term associated with the destination edge is removed during the second pass:

    // Pass 1: accumulate sum_g and sign bits over our slice.
    float my_sum_g = 0.0f;
    unsigned my_signs = 0u;
    int slice_idx = 0;
    for (int k = k_start; k < k_end; k++) {{
        int e = sh_c2e[k];
        int v_idx = sh_nbr[k];
        float v = posterior[v_idx * B + b] - c2v[e * B + b];
        my_signs |= ((unsigned)(v < 0.0f) << slice_idx);
        float av = fabsf(v);
        if (av < 1e-12f) av = 1e-12f;
        float t = tanhf(av * 0.5f);
        if (t > 0.99999988f) t = 0.99999988f;
        float g = -__logf(t);
        my_sum_g += g;
        slice_idx++;
    }}
    int my_count_neg = __popc(my_signs);

    part_sum_g    [wid * BW + tx] = my_sum_g;
    part_count_neg[wid * BW + tx] = my_count_neg;
    __syncthreads();

    // Cross-warp reduction (warp 0 reduces over all warps).
    if (wid == 0) {{
        #pragma unroll
        for (int w = 1; w < N_WARPS; w++) {{
            my_sum_g     += part_sum_g    [w * BW + tx];
            my_count_neg += part_count_neg[w * BW + tx];
        }}
        part_sum_g    [tx] = my_sum_g;
        part_count_neg[tx] = my_count_neg;
    }}
    __syncthreads();

    float total_sum_g = part_sum_g[tx];
    int   total_count_neg = part_count_neg[tx];

    int parity = (total_count_neg + s_idx) & 1;
    float pre = (parity ? -alpha : alpha);

    // Pass 2: write outputs using exclusion (recompute g).
    int slice_idx2 = 0;
    for (int k = k_start; k < k_end; k++) {{
        int e = sh_c2e[k];
        int v_idx = sh_nbr[k];
        float v = posterior[v_idx * B + b] - c2v[e * B + b];
        float av = fabsf(v);
        if (av < 1e-12f) av = 1e-12f;
        float t = tanhf(av * 0.5f);
        if (t > 0.99999988f) t = 0.99999988f;
        float g = -__logf(t);
        float s_excl = total_sum_g - g;
        if (s_excl < 1e-12f) s_excl = 1e-12f;
        float t2 = tanhf(s_excl * 0.5f);
        if (t2 > 0.99999988f) t2 = 0.99999988f;
        float mag_out = -__logf(t2);
        float sign_k = ((my_signs >> slice_idx2) & 1u) ? -1.0f : 1.0f;
        float new_msg = pre * sign_k * mag_out;
        c2v[e * B + b] = new_msg;

The first pass computes the transformed value g for each edge and adds it to total_sum_g. The second pass recomputes g to form the excluded sum s_excl = total_sum_g - g. This avoids storing every edge value and minimizes memory usage. The clamps keep logarithm inputs away from zero and prevent g from rounding exactly to zero.

S1 uses a hybrid schedule: the initial iterations employ sum-product, and the remaining iterations employ the less expensive min-sum update. The Python loop in Section 6e implements this transition.

6c · Posterior-update kernel — layered_var_resync_subset

telescoping_decoder/kernels/s1_layered_bp.py · layered_var_resync_subset

After a layer writes new c2v messages, the posteriors of its incident variables are no longer current. This kernel recomputes \(L_v = \lambda_v + \sum_{c} L_{c\to v}\) for the variables listed in subset_idx; variables not incident on the layer are omitted.

extern "C" __global__ void layered_var_resync_subset(
    const float* __restrict__ c2v,
    const int*   __restrict__ v2e,
    const float* __restrict__ prior,
    const int*   __restrict__ subset_idx,
    const int B, const int n_layer, const int E, const int DV_unused,
    float* __restrict__ posterior
) {{
    int blk = blockIdx.x;
    if (blk >= n_layer) return;
    int v = subset_idx[blk];
    int tx = threadIdx.x;
    int b = blockIdx.y * BW + tx;

    extern __shared__ int sh_v2e[];
    #pragma unroll
    for (int i = 0; i < (DV_PAD + BW - 1) / BW; i++) {{
        int kk = tx + i * BW;
        if (kk < DV_PAD) {{
            sh_v2e[kk] = v2e[v * DV_PAD + kk];
        }}
    }}
    __syncthreads();

    if (b >= B) return;
    float sum = 0.0f;
    #pragma unroll
    for (int k = 0; k < DV_PAD; k++) {{
        sum += c2v[sh_v2e[k] * B + b];
    }}
    posterior[v * B + b] = prior[v * B + b] + sum;
}}

Each of the for loops consists of not too many iterations so we use #pragma unroll to unroll the loops at compile time. This reduces the overhead at runtime and increases instruction pipelining. Unused padded slots in v2e contain the sentinel edge index E. They read from the zero-valued final row of c2v and therefore do not change the sum.

A multi-warp variant exposes additional independent memory operations to the scheduler and thereby hides global-memory latency.

Multi-warp variant: layered_var_resync_subset_mw

telescoping_decoder/kernels/s1_layered_bp.py · layered_var_resync_subset_mw

The mathematical update is unchanged. NWY is the number of warps in the block's y dimension, configured by var_nwy. With the default var_nwy=4, the block shape is (BW=32, NWY=4): four warps process the same variable across disjoint sets of batch lanes. The scheduler can issue work from one warp while another waits on memory:

extern "C" __global__ void layered_var_resync_subset_mw(
    const float* __restrict__ c2v,
    const int*   __restrict__ v2e,
    const float* __restrict__ prior,
    const int*   __restrict__ subset_idx,
    const int B, const int n_layer, const int E, const int DV_unused,
    float* __restrict__ posterior
) {{
    int blk = blockIdx.x;
    if (blk >= n_layer) return;
    int v = subset_idx[blk];
    int tx = threadIdx.x;
    int wy = threadIdx.y;
    int nwy = blockDim.y;
    int b = blockIdx.y * (BW * nwy) + wy * BW + tx;

    extern __shared__ int sh_v2e[];
    int linear_tid = wy * BW + tx;
    int total_threads = BW * nwy;
    #pragma unroll
    for (int i = linear_tid; i < DV_PAD; i += total_threads) {{
        sh_v2e[i] = v2e[v * DV_PAD + i];
    }}
    __syncthreads();

    if (b >= B) return;
    float sum = 0.0f;
    #pragma unroll
    for (int k = 0; k < DV_PAD; k++) {{
        sum += c2v[sh_v2e[k] * B + b];
    }}
    posterior[v * B + b] = prior[v * B + b] + sum;
}}

The incident-edge list is loaded once per block and shared by all four warps. Each warp retains contiguous accesses to c2v[e*B + b..b+31]. This variant is selected by the default setting fast_var_resync=True.

6d · The utility kernels

telescoping_decoder/kernels/s1_layered_bp.py · utility kernels

residual_count — convergence evaluation

This kernel evaluates convergence by recomputing each parity check from the current hard decisions and comparing the result with the observed syndrome. One block is assigned to each check:

extern "C" __global__ void residual_count(
    const float* __restrict__ posterior,
    const int*   __restrict__ c_neighbors_real,
    const int*   __restrict__ c_valid_real,
    const unsigned char* __restrict__ synd,
    const int B, const int m, const int n, const int DC_REAL,
    int* __restrict__ residual,
    unsigned char* __restrict__ unsat
) {
    int c = blockIdx.x;
    int b = blockIdx.y * blockDim.x + threadIdx.x;
    if (b >= B || c >= m) return;
    const int* nbr = c_neighbors_real + (long long)c * DC_REAL;
    const int* val = c_valid_real + (long long)c * DC_REAL;
    int s = 0;
    for (int k = 0; k < DC_REAL; k++) {
        int v = nbr[k];
        if (val[k] && v < n) {
            if (posterior[(long long)v * B + b] < 0.0f) s ^= 1;
        }
    }
    int s_target = synd[(long long)c * B + b];
    int u = (s != s_target) ? 1 : 0;
    unsat[(long long)c * B + b] = (unsigned char)u;
    if (u) atomicAdd(residual + b, 1);
}

The condition residual[b] == 0 is equivalent to satisfaction of every check and hence to \(H\hat{\boldsymbol{\epsilon}}=s\). Multiple check blocks contribute to the residual of the same shot, so the counter is incremented with atomicAdd.

hard_decision — GPU-side thresholding

extern "C" __global__ void hard_decision(
    const float* __restrict__ posterior,  // (n, B)
    const int B, const int n,
    unsigned char* __restrict__ correction  // (n, B) uint8
) {
    // correction[v, b] = (posterior[v, b] < 0) ? 1 : 0
    long long v = blockIdx.x;
    long long b = (long long)blockIdx.y * blockDim.x + threadIdx.x;
    if (b >= B || v >= n) return;
    long long off = v * B + b;
    correction[off] = (posterior[off] < 0.0f) ? 1 : 0;
}

Device-side thresholding avoids transfer of the full floating-point posterior array. The kernel instead produces a compact uint8 correction. Before host transfer, run() also evaluates the observable matrix product and, for GARI, the relevant detector rows. The stage therefore transfers only the compact correction, observable, and acceptance data required by the caller.

The remaining utility kernels scale the prior (scale_prior), retain the lowest-residual posterior over relay legs (copy_better), and reset buffers within a captured graph (zero_buffer_f32/i32). The kernels var_near_unsat and apply_relay_shared support the multi-leg path and are not used by the single-leg S1 configuration.

6e · Orchestration — the BP loop and the CUDA graph

telescoping_decoder/kernels/s1_layered_bp.py · _emit_one_bp_solve, _build_graph, and run

Python launches the kernels through CuPy. The method _emit_one_bp_solve constructs one complete BP solve, including the \(K\)-layer sweep, the hybrid-kernel transition from sum-product to min-sum, and iteration-dependent damping:

ls stands for layer start, and le stands for layer end. A layer contains le - ls checks. The launch grid (le - ls, gy) creates one block along the x dimension for each of those checks, while gy = ⌈B/32⌉ spans the batch dimension.

With the flooding schedule, one launch updates all m checks, after which one variable-resynchronization launch recomputes all n posteriors. Every check in that iteration therefore reads the posterior state that existed before the global resynchronization.

With the layered schedule, _layer_ranges(m, K) divides the check positions into K nearly equal layers. The decoder updates one layer and immediately recomputes only the variables touched by that layer before moving to the next one. Later layers can therefore use posterior information produced by earlier layers in the same BP iteration. In this branch, le - ls is the number of checks in the layer, whereas n_layer = off1 - off0 is the number of distinct variables touched by that layer of checks.

We only ever use the layered schedule but we include the flooding implemenation for completeness. We tested the flooding schedule but found the layered schedule to converge more shots and give lower logical error rates when used in our telescoping decoder pipeline.

CUDA graph capture

A solve launches one check kernel and one posterior-update kernel for every layer and iteration, in addition to setup and residual kernels. Because each GPU operation requires a CUDA kernel launch, issuing many of them from the CPU adds overhead. A CUDA graph records this fixed sequence once, then replays it as one combined launch on later solves. This reduces CPU-to-GPU launch overhead and can make repeated solves faster.

A separate CUDA graph is cached for each batch size \(B\). At decode time, run() copies the input syndrome into pointer-stable GPU buffers and starts the pre-recorded sequence with graph.launch(). The GPU computes the final binary (hard) decision and keeps it on the device while it evaluates obs_pred and, when configured, the GARI relevant-row condition. The low-level API returns only these compact results, the residual, and the uint8 correction. It does not transfer the full floating-point posterior to the CPU or require a correction round trip back to the GPU.

Return values. The method returns a dictionary containing converged (B, bool), correction (B, n, uint8), best_residual (B, int32), and a config label of "S1" for converged shots or "NC" (not-converged) for the rest. When obs_matrix is supplied it also returns obs_pred; the GARI stage additionally requests relevant_converged. The shots that fail the stage's acceptance rule are forwarded to S2.

7 · The S2 relay-BP decoder

S2 extends S1 using the Relay-BP ideas in arXiv:2506.01779. It retains the layered update structure of S1 and augments it with per-iteration memory, repeated BP legs, candidate selection, and a coset-quorum acceptance criterion.

7a · Relay-BP extensions

  1. Per-iteration memory. At every iteration, S2 evaluates \(\Lambda(t) = (1-\gamma)\Lambda_0 + \gamma M(t-1)\) using memory_iter_init (Section 7b).
  2. Per-leg memory strengths. Each variable receives a value \(\gamma_v\) sampled independently from a uniform interval that may contain negative values. The sampled vector is fixed within a leg.
  3. Ordered initial leg. Leg 0 uses the uniform scalar gamma0.
  4. Marginal warm start. Leg \(N\) initializes \(M(0)\) from the final marginal of leg \(N-1\), while resetting the check-to-variable messages.
  5. Constant-\(\alpha\) option. S2 supports a constant damping schedule in addition to the ramp used by S1.
  6. Minimum-weight selection. S2 accumulates converged legs until the configured quorum is reached and retains the converged correction of minimum weight. Section 7d describes the select_* kernels.

7b · The per-iteration memory kernel — memory_iter_init

kernels/s2_relay_bp.py · the relay-memory apply kernel

The kernel memory_iter_init implements the defining memory operation of relay-BP. At the beginning of iteration \(t\), it combines the fixed channel prior \(\Lambda_0\) with the previous marginal \(M(t-1)\). The resulting variable-dependent bias initializes the posterior together with the accumulated check messages:

extern "C" __global__ void memory_iter_init(
    const float* __restrict__ prior_in,   // Lambda0 (n, B)
    const float* __restrict__ M_prev,      // (n, B)
    const float* __restrict__ gamma,       // (n,)
    const float* __restrict__ c2v,         // (E+1, B)
    const int*   __restrict__ v2e,         // (n, DV_PAD)
    const int B, const int n, const int E,
    float* __restrict__ prior_out,         // (n, B)
    float* __restrict__ posterior          // (n, B)
) {{
    int v = blockIdx.x;
    int b = blockIdx.y * BW + threadIdx.x;
    if (b >= B || v >= n) return;
    long long off = (long long)v * B + b;
    float g = gamma[v];
    float bias = (1.0f - g) * prior_in[off] + g * M_prev[off];
    float sum = 0.0f;
    const int* e = v2e + (long long)v * DV_PAD;
    #pragma unroll
    for (int k = 0; k < DV_PAD; k++) {{
        sum += c2v[(long long)e[k] * B + b];
    }}
    prior_out[off] = bias;
    posterior[off] = bias + sum;
}}

The subsequent posterior update retains the form posterior = prior + Σc2v. In S2, however, prior denotes the iteration-dependent bias \(\Lambda(t)\) rather than the static channel prior. Thus, the memory contribution enters through the prior term used by every layer in iteration \(t\).

7c · Memory-strength schedule and warm start

  • Leg 0. All variables use the scalar gamma0, and \(M(0)\) is initialized from the channel prior. This is the ordered \(T_0\) leg.
  • Legs 1 through \(N\). Each \(\gamma_v\) is drawn independently from \(\big[\text{center}-\tfrac{\text{width}}{2},\ \text{center}+\tfrac{\text{width}}{2}\big]\). The default interval includes negative values, and the sampled vector remains fixed throughout the leg.
  • Warm start. Leg \(N\) initializes \(M(0)\) from the final marginal current_post of leg \(N-1\). The c2v messages are reset between legs.
Repeatability. The random seed depends on the prior index, leg, and chunk_start: the current batch's starting row offset within the remaining syndromes. This offset is not a syndrome value or a permanent shot identifier. Results are reproducible for a fixed input order and batch partition. Changing the S2 batch size, shot order, or set of remaining shots may change these offsets and therefore produce a different \(\gamma\) schedule.

7d · Min-weight selection — the select_* state machine

kernels/s2_relay_bp.py · the selection kernels

Multiple relay legs may produce distinct converged corrections. S2 ranks these candidates by the weighted Hamming objective

$$w(\hat{\boldsymbol{\epsilon}}) = \sum_v \hat{\epsilon}_v \cdot \lambda_v \quad(\text{larger } \lambda_v = \text{less likely error}).$$

The kernel compute_weight evaluates this objective with one block per shot. Threads accumulate partial sums over variables, followed by a shared-memory tree reduction.

The following leg-zero kernels initialize the per-shot score arrays and the per-variable candidate, warm-start, and correction arrays:

extern "C" __global__ void select_perb_init(
    const int* __restrict__ residual, const float* __restrict__ weight,
    const int B, const int stop_nconv,
    int* __restrict__ best_res, float* __restrict__ best_weight,
    int* __restrict__ n_conv, unsigned char* __restrict__ found
) {
    int b = blockIdx.x * blockDim.x + threadIdx.x;
    if (b >= B) return;
    int r = residual[b];
    bool conv = (r == 0);
    best_res[b] = r;
    int nc = conv ? 1 : 0;
    n_conv[b] = nc;
    best_weight[b] = conv ? weight[b] : 3.4e38f;
    found[b] = (nc >= stop_nconv) ? 1 : 0;
}

extern "C" __global__ void select_var_init(
    const float* __restrict__ posterior, const int n, const int B,
    float* __restrict__ best_post, float* __restrict__ current_post,
    unsigned char* __restrict__ corr
) {
    int v = blockIdx.x;
    int b = blockIdx.y * blockDim.x + threadIdx.x;
    if (b >= B || v >= n) return;
    long long off = (long long)v * B + b;
    float p = posterior[off];
    best_post[off]    = p;
    current_post[off] = p;
    corr[off] = (p < 0.0f) ? 1 : 0;
}

Leg 0 initializes this state with select_perb_init and select_var_init. Each subsequent leg executes two kernels in the following order:

extern "C" __global__ void select_var_step(
    const float* __restrict__ posterior,
    const int*   __restrict__ residual,
    const float* __restrict__ weight,
    const int*   __restrict__ best_res,
    const float* __restrict__ best_weight,
    const int*   __restrict__ n_conv,
    const unsigned char* __restrict__ found,
    const int stop_nconv, const int n, const int B,
    float* __restrict__ best_post,
    float* __restrict__ current_post,
    unsigned char* __restrict__ corr
) {
    int v = blockIdx.x;
    int b = blockIdx.y * blockDim.x + threadIdx.x;
    if (b >= B || v >= n) return;
    if (found[b]) return;            // frozen: no updates
    int r = residual[b];
    float w = weight[b];
    int nc = n_conv[b];
    bool conv = (r == 0);
    bool take_conv = conv && (w < best_weight[b]);
    bool take_nc   = (!conv) && (nc == 0) && (r < best_res[b]);
    long long off = (long long)v * B + b;
    float p = posterior[off];
    if (take_conv || take_nc) {
        best_post[off] = p;
        corr[off] = (p < 0.0f) ? 1 : 0;
    }
    int nc_after = nc + (conv ? 1 : 0);
    bool frozen_after = (nc_after >= stop_nconv);
    if (!frozen_after) current_post[off] = p;
}
extern "C" __global__ void select_perb_step(
    const int* __restrict__ residual, const float* __restrict__ weight,
    const int B, const int stop_nconv,
    int* __restrict__ best_res, float* __restrict__ best_weight,
    int* __restrict__ n_conv, unsigned char* __restrict__ found
) {
    int b = blockIdx.x * blockDim.x + threadIdx.x;
    if (b >= B) return;
    if (found[b]) return;
    int r = residual[b];
    float w = weight[b];
    int nc = n_conv[b];
    bool conv = (r == 0);
    bool take_conv = conv && (w < best_weight[b]);
    bool take_nc   = (!conv) && (nc == 0) && (r < best_res[b]);
    if (take_conv) best_weight[b] = w;
    if (take_nc)   best_res[b] = r;
    if (conv) { nc += 1; n_conv[b] = nc; }
    found[b] = (nc >= stop_nconv) ? 1 : 0;
}

The ordering is required because select_var_step compares the candidate against the scalar state from the preceding leg, whereas select_perb_step advances that state. The parameter stop_nconv receives the phase value quorum; a shot is frozen after the required number of converged legs has been collected for the coset-agreement test.

Non-converged legs do not count toward quorum. Once quorum legs have converged, their logical cosets must all agree; otherwise the shot is deferred. Thorughout, we only keep track of the lowest weight physical correction found so far.

7e · The relay loop and rebatching

_run_chunk_legs runs all relay legs for one chunk of shots. It loads the syndrome and prior, runs leg 0, samples the \(\gamma\) vectors for the remaining legs, and then runs those legs until every shot freezes or the leg limit is reached. Finally, it copies back the best candidates and applies the coset-quorum test.

_capture_bp_iters records the GPU operations for all BP iterations within one leg. For each iteration, it records the memory initialization, every layered check update and variable resynchronization, and the update that carries the resulting posterior into the next iteration. These recorded iterations become part of leg0_graph and legN_graph. _run_chunk_legs then launches those graphs—leg0_graph for the first leg and legN_graph for each later leg—so each launch executes the complete sequence of BP iterations recorded by _capture_bp_iters.

Rebatching (shrinking a chunk as shots finish). A shot freezes after it has produced enough converged legs for the quorum test. Later legs no longer need to run BP for that shot, so the driver packs the unfinished shots into the smallest available bundle that fits them (32, 64, 96, 128, 256, or 512 columns). It carries over each shot's syndrome, channel prior, warm-start marginal, best candidate, and quorum count. We do not need to copy the the check messages since they are reset every leg. Also, since the \(\gamma\) schedule was sampled for the original chunk before this compaction, rebatching does not affect the reproducibilty of our decoder.

8 · Acceptance criteria

Both the normal S2 kernel and the one tailored for GARI use the same core Relay BP logic.

Coset quorum (both kernels)

S2 collects quorum converged legs and accepts a shot only when they agree on their predictions for all the logical operators. The vector of logical operator predictions is computed as \(L\hat{\boldsymbol{\epsilon}}\bmod 2\) where \(L\) is a matrix whose rows correspond to the support of the logical observables and \(\hat{\boldsymbol{\epsilon}}\) is the converged error vector. This vector of logical operator values is computed by a sparse GPU matrix-vector product. Disagreement causes the shot to be deferred to S3 or S4. S2 returns the agreed vector of logical operator predictions as obs_pred.

GARI variant

For the block-structured GARI decoding system, S2RelayBPGari introduces three additional parameters:

  • conv_rows and residual_count_idx restrict convergence evaluation to the relevant detector rows.
  • weight_llr supplies a weight vector to compute_weight in place of the channel LLR.
  • layers specifies an explicit layer ordering for the block structure.
